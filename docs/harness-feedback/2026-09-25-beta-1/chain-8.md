# chain-8 (app-diagnostics-and-polish), implementer, Sonnet (normal capacity, after the 17:00 reset)

- **What:** `sonarjs/super-linear-regex` fired on a regex (`[^\s()]*\/([^\s/()]+:\d+:\d+)`, and even a simplified `[^\s()]+:\d+:\d+`) that I was confident was linear-time in practice.
  **Mechanism:** lint runs as part of `gate.sh`, so this was only discovered after coding + testing were otherwise done, not at write time.
  **Verdict:** CAUGHT-REAL-MISTAKE (sonarjs's static heuristic was right to be cautious here — a broad path-matching character class overlapping the digit suffix it must also match is exactly the shape that causes backtracking blowups on adversarial input, even though my specific test inputs never triggered one) — but also DRAWBACK in that a shape as simple as `[^\s()]+:\d+:\d+` still trips it, requiring a manual-scan rewrite for something a `.lastIndexOf('/')` one-liner would have solved instantly if only the surrounding match could be regex-free.
  **Cost:** ~2 extra edit/test/lint cycles (maybe 5 minutes) · **Evidence:** `/tmp/lint2.log`, `/tmp/lint3.log`.
- **What:** my first fix for the sonarjs regex flag (replace the "path" quantifier with a callback + `lastIndexOf`) had a real logic bug (overwriting `lastSlash` on every `/` scanned instead of only the first), caught by the exact iOS-shaped-stack test I wrote for 8.1, not by lint or typecheck.
  **Mechanism:** none — this is just me getting the manual backward-scan logic wrong on the first pass · **Verdict:** NEUTRAL (self-inflicted, self-caught by my own test before commit) · **Cost:** one edit/test cycle · **Evidence:** `/tmp/l6.log` failure, fixed in `/tmp/l7.log`.

  **Mechanism:** had to `find` for the actual path before reading · **Verdict:** DRAWBACK (minor — one extra `find`/`grep` round-trip, not a wrong turn) · **Cost:** ~1 minute · **Evidence:** my own early `find`/`grep` commands in this session.
