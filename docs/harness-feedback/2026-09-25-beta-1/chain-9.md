# chain-9 (release-upgrade-check), implementer, Opus

1. **What:** A chain-block fact was false for the old commit: "the dev server without an OpenRouter key uses the stub." At 382511 stub mode needs `WHIM_PIPELINE=stub`, and `/v1/rewrite` answers 502 without a model. **Mechanism:** plan facts described HEAD, and the chain targets an older build. **Verdict:** DRAWBACK. **Cost:** about 10 minutes reading the old server code with `git show a9b03c47:…`. **Evidence:** `a9b03c47:server/src/config.ts:124`, `a9b03c47:server/src/routes/rewrite.ts:297-304`.
2. **What:** Decision 1 ("the device id as the app shows it") assumed a screen that 382511 doesn't have. **Mechanism:** a decision made without checking the old build's UI. **Verdict:** DRAWBACK. **Cost:** a small MMKV reader plus a real-store fixture (about 100 lines and tests). **Evidence:** `git grep getDeviceId a9b03c47` finds no UI use; beta-1 `copy.ts#aiFeaturesStatusLine` shows an outdated grant as "Off".
3. **What:** The seed flow couldn't be run anywhere. The only emulator and all booted simulators belong to the orchestrator (Whim_Verify is free but booting it was out of scope). **Mechanism:** the scope rule (don't boot devices) plus shared devices. **Verdict:** ENV. **Cost:** the flow is checked for syntax and selectors only, so its first real run is 10.5. **Evidence:** `adb devices` showed emulator-5554 (Pixel_10_Pro_XL) with the user's data; `simctl list devices booted` showed four simulators, including Whim-Upgrade-15Plus.
4. **What:** Sonar lint failed the first gate run with 4 errors: `bash` run from PATH in a test, a regex with slow backtracking, an inverted comparison, and one function over the complexity limit. **Mechanism:** the gate's lint step. **Verdict:** CAUGHT-REAL-MISTAKE (the PATH one is real hygiene); the complexity one is NEUTRAL. **Cost:** one extra gate run of about 3 minutes. **Evidence:** gate log, lint section.
5. **What:** The memory note on discriminating red-checks exposed a test that proved nothing: a weaker MMKV parser that ignores the stored data length passed every test. **Mechanism:** the memory note, applied by me (nothing forces it). **Verdict:** CAUGHT-REAL-MISTAKE. **Cost:** about 5 minutes; I added the "every key read is one the launcher writes" assertion. **Evidence:** before the fix, `red1.log` showed 0 failures under the mutated parser; after it, `red2.log` showed the intended failure.
6. **What:** After my own `sed` and `cp` edits, the tools kept warning that files had changed on disk. **Mechanism:** file-state tracking. **Verdict:** NEUTRAL. **Cost:** about 1 minute to re-check that the parser file wasn't still the mutated version. **Evidence:** warnings after the red-check restore.

What helped: the chain block's device facts (`adb reverse`, Maestro seeing into the iframe, the iOS keyboard trap); the memory notes on the Android run recipe, the Xcode 27 simulator build, Maestro and red-checks; the fake-tool pattern in `source-maps.suite.ts`, which made a full hermetic run of the shell script possible; and a live emulator, which gave real fixtures.

What the harness should change:
1. When a chain targets an old release, the dispatch block should check each "fact" at that commit (`git show <tag>:<path>`) before stating it.
2. Give device-tooling chains a throwaway device, or say which booted devices are free to use, so a flow can be smoke-run instead of only syntax-checked.
3. Consider adding `maestro check-syntax` over `scripts/release/upgrade-check/*.yaml` and `demo/**/*.yaml` to gate-full. It is a cheap check for flow files. This needs an owner edit, since gate scripts are protected.
