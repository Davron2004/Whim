# How Whim flows

Phase B of `design-system-v1`. Flow-level changes: fewer steps, clearer places, and the moments between
screens. Screen-level layouts are in `02-screens.md`; components in `03-components.md`; motion moments
(M-numbers) in `05-motion.md`. Evidence comes from the Android capture in
`Whim-evidence/design-audit-2026-10-09/android/` (file names below) and the production flowbench
(`openspec/changes/beta-1/flowbench/after-visible.json`, 22 runs on 2026-09-26).

## The map

Every surface is one of four kinds, and each kind has one way in and one way out.

| Kind | What lives there | Comes from | Leaves by |
|---|---|---|---|
| Root | Your apps | App launch | n/a |
| Full screen | A running app; Update required; Link missing | Its tile (morph), or the system | The orb → "Back to your apps"; Android back at the app's root |
| Pushed screen | History, Settings, Advanced, AI features, Report, on `react-native-screens`' native stack | A row, menu item or text button | Back control and the OS's own gesture: iOS edge and content-area swipe, Android predictive back |
| Sheet | The making flow, the Whim sheet, confirmations, first-run consent | The thing you touched (composer, orb, tile, row) | Close button, drag down, scrim tap, Android back |

The context menu on a tile is the one anchored surface; it closes on any tap outside it and on back.

| Today | Becomes |
|---|---|
| 14 full screens swapped by `setScreen` with hard cuts | 4 full screens, 5 pushed screens, 4 sheet types, 1 menu |
| Compose, Clarify, Plan, Build, Done and Failure as separate screens with a 3-bar step indicator | One making sheet with four pages: Describe, Plan, Making, Ready (or Failure) |
| Age, Terms and Consent as three screens before the first prompt | One first-run sheet, shown only when making the first app |
| Orb menu with four rows, "Change it" leaving the app | Whim sheet with the change field at the top; the app stays open |

## 1. Making an app

### The steps

| Today (capture) | Taps | New | Taps |
|---|---|---|---|
| Composer → Compose screen, type → Continue → Clarify, answer → Continue → Plan (`71`, `72`, which repeats the answers as rows) → Build it → Making → Open it | 5 + answers | Composer → Describe, type → Continue → Plan with the questions inline → Make it → Making → Open | 4, answers optional |

**Clarify and Plan merge into one page.** The capture shows why: clarify asks three questions
(`61-clarify-questions-top`), then the plan repeats those answers as three of its eight rows ("How much
should it hold? A few weeks", `72-plan-bottom`). One page puts the decisions next to what they decide:

- **Questions first, plan under them.** Clarify returns in about 1.8 s (p50) and the plan in about 2.3 s
  more. The page shows the questions as soon as they land, so the person is answering while the plan is still
  being written.
- **"Decide for me" is selected by default** on every question, in the person's voice like every other
  answer. Making an app without touching a chip is the normal path and now looks like it; today "Skip these
  and Whim will pick sensible answers" is a footnote under unselected pills. In multi-select it is exclusive.
- **Answers come at real length.** The model's options run to about 50 characters today; the clarify prompt
  caps them at 40 (an eval case in C2). Options over 20 characters render as full-width radio or checkbox
  rows, short ones as wrapping chips. An answered question collapses to one line ("Brewer · V60"), so the
  plan stays in view.
- **The plan no longer repeats the answers.** The rewrite is told which decisions the questions leave open,
  and the answers travel to generation as `clarifications`, which `GenerateRequest` already carries. This is a
  server prompt change and a client sequencing change; the wire contract stays.
- **Rows still edit in place** (M25), and an edited row shows the person's words as typed.

The step bars go away. With two pages before making, the title ("What should it do?", "Here's the plan")
answers "where am I" on its own.

**What the plan says.** A real plan (`ios/76-plan-real-tracker-light.png`, a habit tracker) runs to four
rows of up to seven lines each, under fixed labels that don't always fit: "WHEN A STEP ENDS" heads the row
about ticking off a habit. The rewrite prompt changes with the merge:

- Labels are written for the app, up to three words, sentence case ("Ticking a habit", "Streaks"), instead
  of a fixed set.
- Each row is at most two sentences (about 140 characters). Detail the person didn't ask about stays out of
  the plan; it can still be in the app.
- Rows never restate an answer to a question on the same page.

### While it's made

The making page has the ember at the top with the ambient light behind it, "Making Pour Timer", the person's
quoted words, the four steps, one honest line about time, and **Stop**. Time copy comes from the production
flowbench: generation took 53 s at the median, 144 s at the 90th percentile and 225 s at worst, so the first
line gives a range.

| Elapsed | Line |
|---|---|
| 0–75 s | "Usually 1–2 min. You can leave; it keeps going." |
| 75–150 s | "Taking longer than most. Still going." |
| Over 150 s | "This one's slow. I'll keep at it; you can leave." |
| No bytes for 40 s | "No word from the server for 40 s. Still waiting." with the ember stuck |
| In line | "Waiting for a free spot. You're next." or "2 ahead of you." with the ember still and dim |

The stream reports `repair` with an `attempt` (`contract/src/index.ts:368`). The step list shows it as a
"Fixing a problem · try 2 of 3" row under the current step, and the current marker moves down to it instead of
jumping back to "Writing the app".

The thresholds live in one constant with the run that measured them, and are re-measured whenever the
flowbench runs before a model change. Later, the server can send live percentiles from its ledger; the copy
doesn't change shape when it does.

What goes: "Connected, waiting for a reply · 0:06" and "Writing · 3,560 characters"
(`81-build-progress-a`, `84-build-progress-d`). They describe the transport, not the making. The step list
says where the work is and the ember says whether it's moving; elapsed time sits on the current step.

**Leaving is the default, and it's safe.** The sheet's close X (or back, a swipe down or a scrim tap) is the
one way out; it collapses the sheet into the ghost tile (M5), which keeps the ember glowing. Tapping that tile
opens the sheet again. **Stop** is the plain action at the bottom of the making page and a row in the ghost
tile's menu, so a typo spotted right after "Make it" costs one tap.

**Closing never loses typed work.** Closed on Describe or Plan, the sheet leaves its draft: the composer reads
"Continue "A timer for my…"", and reopening restores the text, the answers and any plan edits.

### Ready

When the app arrives with the sheet open: the ember flares once and settles into the app's 96 tile as it rises
(M10), the name "Pour Timer", the person's quoted words, "It's on your home screen.", then **Open it** in the
app's tint and a plain **Done**. No live preview of the app in v1: running it before the person opens it would
fire its code, cues, storage writes and timers.
"Report this app" moves out of this moment (`90-done` shows it under the buttons); it lives in the Whim sheet
and History, where the problem will actually be noticed.

When it arrives with the sheet closed: the ghost tile turns into the app's tile in place (M4), the success
haptic plays, and Home shows the toast "Pour Timer is ready · Open". If the person is inside another app, the
orb gets its `ember` dot instead, and the Whim sheet lists the new app.

### When it doesn't work

The failure page (and a failed tile, which opens the same page) keeps one idea from today's screen: say what
happened, what's safe, and the one next step. It loses three stacked full-width buttons and the red title
(`131-failure-terminal-new-app`).

| Kind | Body | Primary | Plain |
|---|---|---|---|
| Couldn't get it to run, and rewording helps | "I tried 3 times and couldn't get it to run. Describing it differently often helps." | Change the description (`ink`) | Try again as it is |
| Couldn't get it to run, rewording won't help | "I tried 3 times and couldn't get it to run." | Try again (`ember`) | |
| The server refused for now | The server's reason, as a notice with a countdown | Try again (`ember`), disabled until the window ends | |
| Needs a newer Whim (`133-failure-fallback-newer-version` offers "Try again" today) | "Finishing this needs the latest Whim." | Update Whim (`ink`) | Not now |
| Stopped when the phone closed Whim | "Making stopped when Whim closed." | Try again (`ember`) | |
| The connection dropped (offline, or the stream cut out, `android/134`, `136`) | "I lost the connection to the server partway through." Never suggests rewording | Try again (`ember`), enabled when the phone is back online | |

- When changing an app, a line with a check says "Your current version still works."
- A connection problem before anything was made (clarify or plan can't reach the server) is not a failure:
  the page stays where it is and shows a `Notice` with Try again. Today that case opens "Couldn't build this
  app" and advises rephrasing (`android/134`).
- Server reason strings ("Could not produce a buildable app after maximum attempts") map to these sentences
  by failure kind; unknown reasons show the server text.
- "What happened" (the run timeline) is a collapsed row at the bottom. The duplicated "What happened / WHAT
  HAPPENED" header in the details sheet (`88-build-details-sheet-empty`) goes away with it.
- **Discard** is a `danger` button in the body, under the page's actions; nothing sits beside the close X.
  Discarding happens at once and the toast offers Undo for 6 s before the attempt is deleted.

### When it can't be made as asked

The plan page shows "I can't make this as asked", the reason, and a card: "I could make this instead: a
packing list you fill in yourself". Primary **Make that instead** (`ember`), plain **Change my idea**. The
server's reason text says "Mini-apps can't fetch live weather" (`67-clarify-limit`); the prompt for the limit
reason gets the glossary ("apps", not "mini-apps").

## 2. Changing an app

Today "Change it" from the orb closes the app, opens the compose screen, and walks the whole flow; the person
next sees their app after reopening it. Changing is the core loop of the product, so it gets the shortest
path.

| From | Path |
|---|---|
| Inside the app | Orb → Whim sheet with "What should change?" already at the top → type → send → the sheet grows into the Plan page for the change → **Make the change** → the sheet collapses into the orb (M5 into the orb) |
| Home | Tile menu → **Change it** → the making sheet opens in change mode |
| History | The current version's **Change it** |

While a change is being made, the app stays open and usable on its current version. The orb's ember glows
with the stream (M20). Tapping the orb shows the change's status at the top of the Whim sheet, with Stop.

When the change lands: the orb flares once and a toast says "Pour Timer changed" with **Reload**. Reload
recreates the realm on the new version (the sanctioned reset, spike2 §5). Nothing reloads by itself, so
nobody loses what they were typing. If the toast is missed, an `ember` dot stays on the orb and a "New version
ready · Reload" row sits at the top of the Whim sheet until the person reloads. Leaving and reopening the app
also gets the new version.

When it fails: the orb shows a danger dot and the toast says "The change didn't work" with **See why**,
opening the failure page in a sheet.

| Taps to a change, from inside the app | Today | New |
|---|---|---|
| | Orb, Change it, Continue, Continue, Make the change, Back to your apps, open the app again: 7, and the app closes | Orb, send, Make the change, Reload: 4, and the app stays open |

## 3. Using an app

- **Opening** grows a `bg` container out of the tile (M2); the tint stays a tile-sized plate with the glyph and
  fades as the app paints, so dark mode never flashes a screen of colour. "Opening…" appears only after
  1.5 s. Today's boot overlay (`120-miniapp-booting`) goes.
- **Leaving:** the orb → Whim sheet → **Back to your apps**, or Android back at the app's root (depth 0 on the
  existing nav-depth seam); both shrink the app back into its tile with `smooth` (M3). No edge swipe over a
  running app in v1 (#67 kept); the reasons and the post-v1 spike are in `01-direction.md` §15.
- **Back inside the app:** the SDK header's back control and Android back.
- **Report from the Whim sheet** pushes inside the sheet on its own small stack, so the running app stays
  underneath and closing the sheet returns to it; Report from History pushes on the native stack.
- **The orb** stays at the bottom (resolves `01-direction.md` §16). A top capsule, the usual answer in other
  mini-app hosts, would cover each app's header, take height from every app, and make apps feel like web pages
  in a wrapper; apps first argues for full-screen apps with a small, quiet control. The occlusion the capture
  shows (`121-miniapp-running-hello-app`, the orb over "Clear done") is handled three ways: the orb is a 44pt
  opaque disc with a 52pt target; it drags between bottom-trailing and bottom-leading (#42), remembered per
  app; and both corners sit inside the `chromeInsetBottom` that `Screen` and `Modal`'s action row pad by. It
  hides while the keyboard is up, on the host's own signal, and never moves because an app asked.
- **When an app crashes:** "This app ran into a problem", with **Reload** (`ink`), a plain **Ask Whim to fix
  it**, which opens the change field prefilled with "Fix the error that stops this app." and the error text
  attached, and a plain **Back to your apps**. The orb stays. A crash becomes a change request instead of a
  dead end, and #67 D7's way home holds.

## 4. History

| Today | New |
|---|---|
| Two-colour title "Hello App history", a Report pill, filter pills ("All 1"), mono labels (`100-history-single-version`) | "History" with the app's tile and name under it; a "Report" text button in the header |
| Going back to a version behind a confirm sheet | Immediate, with a toast: "Back on version 3" and **Undo** |
| Making a copy behind a confirm sheet | Immediate; the copy starts fresh with its own data (#43b), then a toast: "Copy made" and **Open** |
| Six coloured kind badges, "↑ YOU'RE ON THIS ONE" | Neutral kind chips with icons; a `Current` badge |
| Filter pills by kind | Removed. Most apps have under 20 versions; a filter costs a row of chrome for a search nobody does |

Going back is safe to do without asking because every version stays in History and the newer one is one tap
away; Undo makes that visible. The button says **Use this version**; prose may still say "go back". Toasts
pause while a screen reader runs, and every Undo stays reachable from History after the toast is gone. When going back would hide saved data, the expanded row says so before the tap:
"Some saved data won't show in this version. It isn't deleted and comes back when you return."

## 5. Your apps (home)

- **Title** "Your apps" in `largeTitle` and a settings button. The "Whim" title and the "YOUR APPS" eyebrow
  (`01-home-first-launch-examples`) said the same thing twice; the brand is in the composer's ember, its
  ambient light and the app icon (resolves `01-direction.md` §16).
- **Grid:** 4 columns of glyph tiles (`04-mini-app-icons.md`), names wrapping to two lines; three columns from
  135% text and a list from 200%. Apps being made come first, then failed and stopped attempts from the last
  day, then apps, each newest first. Attempts older than a day collapse into one "2 didn't work" tile at the
  end of the grid. An app doesn't move when it changes, so places stay learnable.
- **Search** appears under the title once there are 13 apps.
- **Composer** at the bottom, always reachable, morphing into the making sheet (M6).
- **Offline:** a neutral notice under the title: "Offline. Your apps still work; making new ones needs a
  connection." Today it is a 6pt grey dot. It follows
  connectivity as it changes, rather than appearing only after a relaunch (`android/27`).
- **Long-press** gives the context menu (M12), headed by the app's full name: Open, Change it, History, Make a
  copy, Customize tile, Share link, then Delete. Today's sheet has eight rows including two red ones (Delete
  and Dismiss, `09-home-tile-menu-with-dismiss`).
- **Delete** happens at once as a soft delete: the tile leaves (M18) and a toast "Pour Timer deleted" offers
  **Undo** for 10 s; the app and its data are purged after. No confirm sheet. Today it's the platform's alert
  with uppercase CANCEL and DELETE (`07-delete-native-alert`).
- **Share link** opens the platform share sheet with the app link. Today a custom sheet shows the URL and
  tells you to press and hold it (`05-app-link-sheet`).
- **Copies** read "Copy" on their second line and take the tint farthest from the original among the least
  used.
- **Empty** (every app deleted): the ember, still, "Make your first app", and three idea chips that open the
  making sheet with the idea filled in.

## 6. First run

Today: home with three examples; the first tap on the composer walks Age (silent unless blocked), Terms, then
Consent, each a full screen (`10-terms-en`, `14`–`16-consent-ask`), before compose opens.

New: the first tap on the composer opens one sheet, "Before Whim makes apps for you":

1. A short summary in three rows with icons: what's sent, what stays on your phone, what we never do.
2. Links to the full privacy policy and terms, and a "Full details" row that expands the complete consent
   text in place.
3. A Language row in the body (English, Français).
4. A checkbox row "I accept the Terms of use", unticked by default, that must be ticked; the Terms link sits
   outside the checkbox's hit area.
5. **Agree to send descriptions** (`ink`), enabled once the terms row is ticked; **Not now** under it. The
   button names the second act, so both acts are distinct.

Two separate acts (accepting the terms, agreeing to the data use) on one sheet instead of two screens. They stay
two acts on purpose: consent to data use should be distinguishable from accepting terms (GDPR article 7(2)),
and both are still recorded with their versions as today. The legal text itself doesn't change here.

Age stays silent: the store's answer arrives within its 3 s deadline while the sheet is open, and only a
blocked answer shows its own screen.

The examples stay as normal apps and keep their "Example" label (#42). Their History says "Made by Whim as an
example".

## 7. Settings

The owner's note sets the rule: common settings first, diagnostic controls one level down.

| Level | Rows |
|---|---|
| Settings | AI features (subtitle "Review what's sent", opens the review screen) · Language › · About: Privacy policy ↗, Terms of use ↗, Support ↗, Version · Advanced › |
| Advanced | Send error details (switch, with its explanation as the group footer) · This phone: Phone ID (truncated in the middle, with a copy button), Make a new ID (confirm sheet) · Server: two rows, Whim's server ✓ and Your own server › (confirm sheet) |
| Your own server | The one-time acknowledgement (#70) the first time, then the address field and its check line. The address stays saved when you switch back to Whim's server, so choosing either row is a plain selection with nothing to lose; today "Use Whim's server" wipes the address in one tap, in the spot the Advanced header occupied a moment earlier (`android/36`) |

- **Highlighting** is removed (resolves `01-direction.md` §16). The simplified marks pass contrast and
  survive being rendered flat; the switch was an accessibility hedge and an experiment flag, and both jobs
  are done.
- No in-app Reduce Motion switch. The system setting is honoured everywhere, including inside apps (from the
  next open); a second switch would be a setting to explain.
- Each row is a grouped-list row, not a separate card per row (`30-settings-top`).

## 8. Platform behaviour

| Surface | iOS | Android |
|---|---|---|
| Pushed screen | Native stack: back chevron; edge and content-area swipe pop interactively | Native stack: back arrow; predictive back previews the pop |
| Sheet | Drag down; close button; scrim tap | Same, plus back closes it |
| Running app | SDK header back inside the app; the orb → "Back to your apps" closes it into its tile; no edge swipe in v1 | Back goes back in the app, then closes it into its tile |
| Making sheet | Close, drag down or scrim tap leaves it running and keeps the draft | Back leaves it running and keeps the draft |
| Context menu | Tap outside | Tap outside or back |
| Text in apps | Follows Dynamic Type through the theme's `fontScale`, from the next open | Follows the font size setting the same way |
