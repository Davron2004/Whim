4cHow a change gets classified — and icons vs words
The reliable signal

Don't ask a model "was this a buff or a nerf" — it has no ground truth. But you already have one: the plan. Every build has a structured plan before and after. Diff the two and the class falls out mechanically — a plan section appeared, disappeared, changed value, or only its look changed. Plus one class the system knows for certain: a build the repair loop had to rescue.

Five classes, plus a start
ADDEDa plan section that wasn't there before
CHANGEDsame section, different behaviour
LOOKonly the appearance section moved
FIXEDthe repair loop ran — system-known, never guessed
REMOVEDa section disappeared
STARTversion one, only ever one of them

When a build changes several sections, label it by the biggest one: added > removed > changed > look. One badge per version — two badges and people stop reading them.

Why 4b changed shape

Five stories, ordered by how often they'll actually happen. (1) “I asked for one thing, it made the app worse” — seconds after a build, inside the app, and the user wants one button. (2) “It broke and Whim fixed it — what did it do to my app?” — needs one card, right after the repair. (3) “I'm about to ask for something else, what state is this in?” — needs the last two or three prompts, no more. (4) “This has drifted over a week, put it back to Tuesday” — rare, deliberate, wants the full list. (5) “I want a decaf copy of this” — rare, and it's a fork, not history.

1–3 are the same story: the most recent change, and undo. That's not browsing — a scrubber makes you navigate to reach a button you always want. Only 4 is real history, and it deserves the whole screen. So: not mutually exclusive, but not two views of the same thing either. 4b is undo with context; 4a is the archive. The tell that this is right — 4b never needs to scroll, and 4a never needs to be fast.

3cWhy these four, and why nothing else
On the wheel
Up · Change it — the most-used action, so it gets the easiest flick.
Right · Home — what the button does today; muscle memory survives.
Down · Versions — read-only. Restoring happens from inside, with a confirm.
Left · Copy — the only consequential one, so it opens a sheet rather than firing.
Deliberately not on it
Delete, rename, restore, share, export. Anything you can't undo with one tap lives in a full screen where it can be read. A flick should never be the last step of a decision.
Four, not six
Cardinal directions are the only ones people hit reliably without looking. Eight sectors halves the target and kills the whole point of the gesture. If a fifth action earns its place, it goes in the tapped menu only — the menu can be longer than the wheel.
About your audience
You don't have to decide. The tap-menu is the whole feature for a first-timer; the wheel is the same feature for you, faster. The menu labels each action with its direction, so the shortcut is discovered by using the slow path — no tutorial, no settings toggle.
