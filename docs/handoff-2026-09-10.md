A builder was editing `LauncherRoot.tsx`, `BuildStep.tsx`, `RunDetailsSheet.tsx`, `prompt-flow.ts` and tests for the back-button fix when the budget ran out. The working tree may hold a half-applied diff (a `buildBackAction` helper, `onCancel` prop removal from BuildStep). Either finish it or `git checkout -- src/host/launcher` and redo from the spec below.

**Bug:** on the build screen with the details sheet open, hardware back cancelled the whole generation and left no interrupted tile. **Cause:** `BuildStep.tsx` registers its back listener with deps `[onCancel]`; LauncherRoot passes a fresh arrow each render and the screen re-renders every second, so BuildStep is always the newest listener and runs before the sheet's. **Decisions:** (1) hardware back on the build screen = "Leave it running", never cancel; (2) no reliance on listener order: BuildStep calls one stable `onBack`, LauncherRoot's build `onBack` closes the sheet if open, otherwise leaves running; delete LauncherRoot's separate sheet listener. The `prompt-flow` spec's cancellation requirement ("clean cancellation that deletes the pending record" via back) is superseded; update the spec when convenient.

After that: rebuild the APK, smoke on the emulator (open any app: no Tip Splitter flash before the real app; back on the build screen goes home with the ghost tile kept; back with the sheet open closes the sheet), then merge.
