# Store console answers (draft — confirm in each console before submitting)

None of this is uploaded by the release tooling. It exists so the person filling in App Store
Connect and the Play Console types the same answer everywhere, and so a reviewer of this file can
see where each answer comes from. See `openspec/changes/platform-release-readiness/handoff/
store-content.md` for the schemas the sibling JSON files follow.

## Publisher and pricing

- **Publisher / developer account name:** AnyCognition Inc.
- **Copyright:** `2026 AnyCognition Inc.` — `release/store/app-store/copyright.txt`.
- **Price:** Free, both stores. No in-app purchases, no subscriptions.
- **Categories:** Productivity (primary), Utilities (secondary) — design D11.

## Availability

- **Territories:** All App Store and Play territories except mainland China. China requires a
  filing for generative-AI services (the Cyberspace Administration of China's algorithm/generative
  AI registration) that Whim does not have; the server that writes mini-app code is exactly the
  kind of service that filing covers. Hong Kong, Macau and Taiwan are unaffected — they are
  separate storefront territories from mainland China on both platforms.

## Target audience and age rating

- **Target audience:** 13+ on both stores.
- **App Store age rating:** `ageRatingOverrideV2 = THIRTEEN_PLUS` in `release/store/app-store/
  age-rating.json`, with every one of Whim's own content descriptors set to `NONE` — design D11
  ("Whim's own content descriptors are all none, so 13+ comes from the override"). Whim generates
  arbitrary small apps from a user's own words, which App Store Connect's own age-ratings guidance
  treats as user-generated content requiring at least a 13+ floor, independent of Whim's own
  content.
- **Play IARC questionnaire:** answer "yes" to "does the app allow users to generate content using
  AI" and "no" to camera/location/contacts/personal-data collection questions beyond the anonymous
  device ID described below. Target age group 13 and over. Google Play then computes the IARC
  rating from those answers; there is no override field to set directly, unlike App Store Connect.

## AI-generated content declaration

- Both stores ask, in different words, whether the app can generate content with AI. Answer
  **yes**: every mini-app's code and behavior is generated by AI models reached through
  OpenRouter, per `openspec/changes/store-launch-compliance/design.md` D5's disclosure ("The
  server uses AI models from other companies, reached through OpenRouter, to write the app") and
  `docs/store/review-notes.md` §2's guideline 4.7.1 write-up.

## Data safety / App Privacy (source: store-launch-compliance design D5, this change's design D11)

- **What is collected:** user content (the request text, the user's answers to Whim's questions,
  and the approved plan; for an edit of an existing app, also its code, current description and
  data layout — never the rows the user has saved inside the app) and an anonymous per-install
  device ID sent in `x-whim-device`.
- **Why:** user content is sent to AnyCognition's server so it can call third-party AI models
  through OpenRouter and write or change the app (app functionality). The device ID is used for
  daily generation limits and abuse prevention (app functionality, fraud prevention).
- **Sharing:** user content is shared with AI model providers through OpenRouter for app
  functionality. The device ID is not shared with anyone.
- **Linkage / tracking:** neither type is linked to an identity and neither is used for tracking —
  there are no accounts, no login, and Whim never asks for a name, email or phone number.
- **Encryption in transit:** yes, for every request.
- **Full schemas:** `release/store/app-store/app-privacy.json`, `release/store/play/
  data-safety.json`, cross-checked against `ios/Whim/PrivacyInfo.xcprivacy` by
  `checkStoreListing`.

## Reports (source: `openspec/changes/store-launch-compliance/specs/content-reporting/spec.md`)

- A report a user sends about a mini-app carries a reason, an optional note, and — each with its
  own on/off switch, on by default — the app name, the prompt that made the reported version, and
  its code. Reports are stored server-side for 90 days and are not otherwise shared.

## Server persistence otherwise (source: generation-server / usage-ledger spec)

- A content-free usage ledger: device ID, request kind, day, outcome, token counts and cost, kept
  for 90 days. No prompt or generated code is kept in the ledger.

## App access (for reviewer instructions)

- **Login:** none. There are no accounts, so there is nothing for App Review or Play's reviewer to
  sign in with. `docs/store/review-notes.md` §1 walks through trying the app with no credentials.
- **Ads:** none. Whim ships no ad SDK and no analytics or crash-reporting SDK.
- **User-to-user content / social features:** none. Nothing a user makes is visible to any other
  user.

## Device and Network Abuse exemption (Play)

- Requested because Whim's mini-apps run arbitrary JavaScript inside a sandboxed WebView with no
  access to the network, camera, location, contacts or files (`docs/store/review-notes.md` §2,
  guideline 4.7.2/4.7.3 write-up) — the same shape Play's declaration form asks about for
  JavaScript interpreters embedded in an app, not a native abuse vector.
