## 1. The index as the authority, and the route's tests

- [ ] 1.1 In `src/host/launcher/store-access.ts`, export `AppGoneError` and make `update`, `continueSharingData` and `fork` re-read their entry from the index as the first statement inside their `serial` section, before any version-store, journal, index or file write. When the index has no record for `entry.id`, reject with `AppGoneError` and write nothing. Otherwise act on the index's record, not the caller's object: `update` sets `storageGroupId` on the record it writes from the index's (present or absent), the way it already does `tileOverride`; `fork` copies from `engineAppId` of the index's record; `continueSharingData` joins the group of the index's record; and both build the new entry (`lineageEntry`: name, record, tile) from the index's record. The check sits above `ensureLineage` in `update` and above `forkLineage` in the other two. `update` keeps its existing re-read of the index after the snapshot await for `tileOverride`, so a tile choice made during the snapshot is not lost; the group may come from either read, since `remove` cannot run in between. Change nothing else in `update` (`entry.name` stays unrefreshed; §34 pins that). `remove` keeps taking the caller's entry: a purge finishes from its marker's stored copy after the index record is gone. `deliverResult` needs no change; the error fails the delivery like any other.
- [ ] 1.2 In `src/host/launcher/app-index.ts`, make `put` append the id to `order` first whenever `order` does not hold it, and then write the record. An id already in `order` gets one record write and no `order` write. A record an older build left out of `order` is listed again the next time it is put. `list()` already drops an `order` id with no record and `has()` reads the record, so no reader changes.
- [ ] 1.3 Add `src/host/launcher/test/shared-group.suite.ts`, registered from `src/host/launcher/test/acceptance.ts` beside the data-copy suites, on the file-backed rig in `data-copy-rig.ts` (`accessOver`, `newDeviceState`, `withEngine`, `fileOf`, `filesOf`, `sha256`). Build every group with `continueSharingData`, write rows through a real engine, and read them back through `engineAppId` after the operation. Cases:
  - `index authority: a rebuild keeps a sharer in its group, and it still reads its founder's data`.
  - `index authority: a continuation's first build lands in the original's group`: the real `deliverResult` behind the tip with a real `StoreAccess` from `accessOver` (the `tile: a behind-tip rebuild…` test in `build-lifecycle.suite.ts` shows the calls, on a map-backed rig this case does not reuse), then read the original's rows through the new entry.
  - `index authority: the caller's object cannot move an app between stores`: `update` with a sharer's entry whose `storageGroupId` is removed, with one naming another existing app, and with an ungrouped app's entry given a group. The written record matches the index each time.
  - `index authority: going back, a tile change and delete-then-Undo leave a sharer's group and data alone`: `rollback`, `setTileOverride`, `clearTileOverride`, then arm the purge and undo it.
  - `index authority: a build that lands after its app was deleted writes nothing`: sharer B with a copy C (so the repo lives), B removed. `deliverResult` at the tip and behind it both reject with `AppGoneError`; the index has no B and no new entry, the version store has no new version, and no file exists under B's id or its former group's id once the last member is gone.   - `index authority: a copy is not made from an app the index no longer holds`: `fork(stale, undefined, { data })` for both `data` values rejects with `AppGoneError`; the journal, the version store's lineages and the directory are unchanged.

A fresh `StoreAccess` over the same state then reports no entry for the copy's id, and `sweepDataCopies` deletes its file and clears the journal. A direct `index.put` of that same id afterwards lists it once, and so does a `put` of a record that exists but is missing from `order`.

Restore the code after each.
