## chain-0: bootstrap-harness-dependencies — HUMAN-BOOTSTRAP

- tasks: 1.1–1.3
- rationale: Adding a runtime dependency needs `npm install`, which agents are denied, and `docs/harness.md` puts dependency adds permanently human-in-the-loop. `server/package.json` and `package-lock.json` are protected Class-1 files and sit in gate.sh's `CONFIG_SET` tripwire, so the gate refuses any chain that changes them. The budget test update must land in the same commit or the gate goes red.
- reads: specs/generation-server/spec.md §Server workspace and runtime; design.md D3
- writes-contract: none (the pinned set and versions are stated in the spec and read from the lockfile)
- exact edits (human applies):
  - `server/package.json` `dependencies` += `esbuild`, `playwright`, `typescript` at the lockfile-resolved root versions, exact (no `^`)
  - `package-lock.json` regenerated by that one `npm install --workspace server --save-exact …`
  - `server/test/contract.suite.ts` dependency-budget section only: the allowed set gains the three, plus an exact-pin equality check against the lockfile's root resolution
- contingency touchpoint (human, only if it fires at gate-full): if knip reports `esbuild`/`playwright`/`typescript` as unused dependencies of the `server` workspace (they are imported from `synthrun/` and `checks/`, outside the workspace directory), add them to that workspace's `ignoreDependencies` in `knip.json`. This follows the fix-vs-relax checklist: a cross-workspace import false positive, not a silenced real finding.
