## Current behavior
`openRun` opens a fresh context+page, awaits `opts.beforeNavigate`, then navigates with `waitUntil:'load'`. `report.ts` composes that hook as: `attachObserversEarly` (CDP `Runtime.enable` + `Runtime.exceptionThrown` handler, closing over a mutable `sourceMap` slot) → `wireCapabilityBridge`'s `context.exposeFunction('whimHostDispatch', …)` → any caller hook. Only after `page.goto` resolves does `early.finish(ctx)` run: `page.exposeFunction('__whimSynthRelay', …)`, then a **main-frame** `page.evaluate` that installs `globalThis.ReactNativeWebView = {postMessage(s){relay(s)}}`, then `page.on('console')`.

So between document commit and `load`+finish there is no transport at all: `assemble.mjs`'s `toRN()` guards on `if(window.ReactNativeWebView)` and silently drops the frame; `rnLog()` does the same (its console fallback also predates the console listener). Everything the outer page emits in that window is lost: the trusted `delivery`/`paint`/`error`/`probes` frames, the untrusted `rejected-forgery`/`ui-event`/`nav-depth` frames, `syscall` frames when the sink is not `exposed` (it is `exposed` here), the generic authenticated fall-through at `assemble.mjs:152`, and `{__whimHostLog:true,line}` log frames (the relay callback bumps `lastActivityAtMs` then drops them for having no `kind`).

`awaitMount` polls `state.paintAtMs`/`state.diagnostics` for `mountBudgetMs` (default 8000; suites override to 800–3000) and pushes `mount_timeout` on expiry. `recordProbesOutcome` sets `state.contained` from the trusted `probes` payload — to `null` if `payload.contained` is not a boolean — and pushes `containment_failure` only on explicit `false`. `report.ts:132` then emits `obs.state.contained === true`, so "no probes frame ever arrived" and "probes reported a breach" are indistinguishable downstream; the same object collapses a second null at `:141` (`paintAtMs ?? budgets.mountBudgetMs`). Note `containment_failure` *is* pushed for genuine `false`, so `ok`/`diagnostics` still differ between the two cases even though `contained` does not.

## Constraints and invariants
- **Nonce authentication lives entirely in the outer page and is independent of relay timing.** The nonce is minted inside `makeIframe()` (`assemble.mjs:131`) at page-script end; `authentic = (!!nonce && m.nonce===nonce)` (`:145`) is evaluated before any `toRN({trusted:true})`. `observe.ts` consumes `msg.trusted` and never re-derives it. The relay is a pure downstream sink, so opening it earlier cannot by itself admit an unauthenticated frame — **provided the installation stays confined to the outer/main frame.** Today `page.evaluate` guarantees that. Anything that runs per-document in *every* frame would also define `ReactNativeWebView` inside the opaque-origin sandbox realm, where `src/runtime/web/loader.js:65` already defines its own same-named stub and `probes.js:81-82` asserts `window.parent.ReactNativeWebView` is unreachable (decisions #35/#37, F4).
- **The production page, CSP and loader may not be forked, patched or loosened to ease testing** (spec `:24`); `invariants/` and `build/*` are consumed strictly read-only, and both are hard-blocked for subagents by `.claude/hooks/protect-harness.sh:115-116` — a fix reaching `assemble.mjs`/`loader.js` is HUMAN-BOOTSTRAP Class 2 by construction.
- **Every failure-grade signal stays trusted-vantage** (spec `:33`); the forged-verdict scenario (`:35-38`) must keep holding — acceptance `:409` and `:719-749` assert the forgery is recorded as `rejected-forgery` and the genuine verdict still wins.
- `RunReport.contained` is typed `boolean` (`contract.ts:114`). Its consumers: `server/src/generation/stages/run.ts:54` (an `=== false` test that today catches the collapsed null and zeroes diagnostics per D7), `evals/adapters/synthetic-run.ts:36`, plus fixtures/tests `server/test/e2e.ts` (`fakeReport`, `containedDetail`, `:190-243`, `:294`) and `evals/test/fixtures/synthetic-run-report.json`. `evals/contract.ts`'s `ContainmentVerdict` already carries a separate `authenticated: boolean`, and `tier-a.ts:25` already fails an un-authenticated verdict — the adapter hardcodes `authenticated: true` with a docstring justifying it *because* synthrun collapses.
- `RunReport.timings.bootMs` and `mountToPaintMs` are both anchored on `RunContext.startedAt = bootStart`; changing `waitUntil` changes what `bootMs` measures. Spec `:15-20` requires determinism "timings aside".
- `withTotalBudget` and `sweepApp` assume a live, loaded page; `awaitMount` is called *before* `withTotalBudget` in `report.ts`, i.e. outside the total budget.

## Integration points
- `SynthRunSession.openRun` (`session.ts:98-108`) — the `newPage`/`beforeNavigate`/`goto` sequence and the `waitUntil`/`timeout` arguments.
- `RunOptions.beforeNavigate` (`contract.ts:96`) — the existing multi-concern pre-navigation seam (observers, then `whimHostDispatch`, then caller); already documented as "must be live before the delivered page's inline scripts run".
- `EarlyObservers` / `attachObserversEarly` / `finish(ctx)` (`observe.ts:97-107`, `:265-358`) — the phase split itself; `finish` currently also supplies `sourceMap` and `ctx.startedAt`, which the relay callback needs for `atMs`.
- `openObservedRun` (`observe.ts:366-381`) — the convenience composition used by the acceptance suite; `report.ts:56-66` — the production composition. Both call `finish` immediately after `openRun`.
- `recordProbesOutcome` (`observe.ts:212-223`) and `report.ts:126-148` — where a null/false distinction would be produced and where it is currently erased.
- `evals/adapters/synthetic-run.ts:36` — the one place a preserved distinction could reach `ContainmentVerdict.authenticated` without changing `RunReport`'s field type.

## Risks and unknowns
- **I did not verify** whether Playwright's `page.exposeFunction` binding (`__whimSynthRelay`) is currently installed into the sandboxed opaque-origin srcdoc iframe as well as the main frame. Playwright documents bindings as page-wide/all-frames; if that includes the sandbox realm, a *pre-existing* named function is reachable from candidate code today. I did not find any probe or invariant asserting its absence.
- **I did not verify** experimentally whether an `exposeFunction` binding or a main-frame `evaluate`-installed global survives navigation, nor the behaviour of `waitUntil:'commit'` with a `file://` URL under this Chromium.
- **I did not verify** what happens to `page.goto`'s 20 s timeout under an *unbounded* synchronous candidate hang (the fixture the quarantined test would need). Under `waitUntil:'load'` the goto would presumably time out and throw out of `openRun` before `awaitMount` ever runs — I traced the code path (`session.ts:100-105`, catch at `:117`) but did not run it.
- **I did not read** the corpus-eval spec's own requirement text for Tier A's "authenticated vantages" clause; I read only `tier-a.ts` and its docstring.
- `invariants/` does **not** import synthrun; its runners (`invariants/sandbox-isolation/run-against-build.mjs:42`, `bridge/runner.mjs:72-75`) do their own `exposeFunction`-then-`goto` and read verdicts from page state rather than a relay. No edit to `invariants/` is implied by anything I found — flagging only that `probes.js`/`loader.js` mirrors live there and are owner-authored.
- Test coverage today: `npm run synthrun:test` (gate-**full** only, `scripts/gate-full.sh:40`), `npm run server:test` and `npm run evals:test` (fast gate, `scripts/gate.sh:61,64`). Red-checkable: the acceptance suite's stub-based `awaitMount` timeout pair (`:485-493`) is the current non-vacuity anchor; `server/test/e2e.ts:113-116` already red-checks that `contained:true` is not hardcoded; `evals/test/tier-a.test.ts:76-83` already exercises the `authenticated:false` path. The quarantined case needs a fixture whose hang is unbounded (never paints) *and* a run path that reaches `awaitMount` at all — i.e. the observation window open before any paint could be posted, and navigation not gated on a `load` the fixture prevents.
