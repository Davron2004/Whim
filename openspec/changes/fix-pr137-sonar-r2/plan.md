**Cross-lane rule (S7503, async without await):** dropping `async` and returning `Promise.resolve(work())` is NOT equivalent when `work()` can throw (SQLite errors, validation): `async` turns a throw into a rejection, the plain form throws synchronously, and callers like `store.purge().catch(…)` would get an uncaught exception. Every converted method must keep throws as rejections, via ONE shared helper `settle<T>(fn: () => T): Promise<T>` (= `new Promise((resolve) => resolve(fn()))`) in `server/src/settle.ts` (created by lane R2-C; R2-A/R2-B create an identical file if R2-C hasn't merged — orchestrator dedups at merge). Methods whose body cannot throw may use `Promise.resolve`. A conformance/unit test pins "a failing sync store rejects, never throws synchronously" once (R2-C).
**S1186 (empty close):** a no-op `close` returns `Promise.resolve()` with a one-line reason; not an empty async body.
**S9382 (await in loop):** convert to bounded parallelism only where the iterations are independent AND unordered AND the batch is bounded; where order or bounded concurrency is the point (batched deletes, paging, transactional day rebuilds), keep it and list it as an ACCEPT candidate with a one-sentence justification (the owner marks it in Sonar).
