## What changed
- **Fixtures** (`fixtures/{tip-splitter,water-counter,style-gallery}.app.tsx`): dropped `tileColor` and its
  comment. All three already declared tint/icon matching `EXAMPLE_TILES` (slate/receipt, blue/glass-water,
  purple/palette); nothing added. Rebuilt `APP_RECORDS` carries tint/icon and no tileColor (checked).
- **Deleted modules**: `src/host/launcher/tiles.ts` (+ `index.ts` export; no caller left),
  `src/host/launcher/manifest-tile-color.ts`, `src/sdk/design-tokens.ts` (`appColor`, `SHELL_COLORS`,
  `STATUS_COLORS`, `STATUS_COLORS_ON_INK`; unread outside itself and its tests; not on the vc-sdk surface:
  `src/sdk/index.tsx` only re-exports `type WhimTheme` from theme.ts) and theme.ts's `export *` of it.
- **build-lifecycle.ts**: `mapWireRecord(appId, wire)` has no fallback parameter. The lift is inlined: a string
  `tileColor` stays on the record verbatim, a non-string one is dropped. `deliverResult` no longer injects
  `ghostTileColorFor` on install or preserves `editing.record.manifest.tileColor` on rebuild. The rebuild case
  is safe because `StoreAccess.update` writes `assignedTile(current)` down, which a red-check confirmed.
- **prompt-flow.ts**: `ghostTileColorFor` and the `appColor` import removed (design.md D5: tiles being made are ember).
- **Comments**: tile-identity.ts `EXAMPLE_TILES`, bridge `AppManifest.tileColor`, SDK `defineApp.tileColor`
  doc (no longer promises `appColor`), store-access `update` name note, tints.ts djb2 note. Also the #226 items:
  KeyboardShell.tsx now cites "Text input keeps its field and action above the keyboard". app-busy.ts and
  app-busy.suite.ts now cite "Forking creates an independent launcher entry" in place of the removed
  "Fork and delete show a busy state…". Delete is no longer a busy op (only open/fork call `runAppOp`).
- **design-system.suite.ts**: dropped the EXEMPT entry for the deleted design-tokens.ts. A stale entry fails the suite.

## Tests rewritten (all assert tint/icon or the kept legacy read path)
- tile-colour.suite: the 3 `tileColor()` tests became 3 `declaredTile` legacy-hex tests: tint light value
  maps to that tint; a non-hex or non-string value maps to the app-id fallback; a reserved hue maps to its
  nearest tint and is never shown as itself. The shipped-records test now checks
  `APP_RECORDS[id].manifest.tint[0] === EXAMPLE_TILES[id].tint`, the icon too, and no tileColor. The #127 mimic is
  built from tint/icon. The legacy `tileOf` test gained a non-vacuity sanity check.
- build-lifecycle.suite: the 5 ghost-colour tests became 6. Two are mapWireRecord narrowing tests (moved from
  the lift tests). One checks that an install whose wire has only a hex gets the nearest tint (real StoreAccess). One
  rebuilds a pre-tint record and checks the tile is kept (real StoreAccess, pinned id). Two existing rebuild tests were renamed.
- version-record.suite ~:368: was vacuous (undefined === undefined). Now it seeds a pre-tint water-counter
  record with `tileColor`, then asserts manifest.json omits it and the launch keeps it.
- checks/test/acceptance.ts: the examples test now asserts the extracted first tint and icon equal `EXAMPLE_TILES`,
  no tileColor, and pairwise distinct tints and glyphs.
- product-verbs.suite: dropped the `tileColor('Water Counter')` hex string from the copy list. Its assertion is in a loop, so the static count is unchanged.
