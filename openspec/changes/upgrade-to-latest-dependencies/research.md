## Constraints and invariants
- Four containment legs (#35/#37/#74). The Android leg depends on the `RNCWebViewManager`/`RNCWebViewWrapper` class names and `createViewInstance` ordering; `native-network-deny.suite.ts:180-228` checks them by regex, so a renamed upstream symbol fails the gate. The iOS leg depends on the `WKWebView` initializer swizzle.
- Every bridgeless TurboModule spec shape in `src/native/*.ts` must still pass codegen (DEVLOG.md:546).
- Hermes prerequisites: fill only what is missing; the import stays first in index.js (spec hermes-runtime-prerequisites).
- Version store: polyfills load before isomorphic-git (#36/#39). Data written by MMKV v4 and op-sqlite must survive an app upgrade (release upgrade check).
- Generation transport: exactly one POST per generation, no post-hoc fetch fallback (#58 D1).
- `textZoom={100}` stays (`mini-app-host-ui.suite.tsx:496-513` asserts it).
- `tsconfigRaw: '{}'` in esbuild bundling, so the project tsconfig's `jsx` never leaks into mini-app bundles (H1b).
- Workspaces must not shadow `react` (guard:metro).

## Integration points
- package.json/package-lock.json → `pod install` (Podfile.lock) → the Gradle plugin's AGP/Kotlin pick; `kotlinVersion`/`ndkVersion` ext values, the JDK pin and the Gradle wrapper sit next to the RN plugin.
- MainApplication.kt/MainActivity.kt and AppDelegate.swift/SceneDelegate.swift — the RN host entry points the upgrade template diffs touch.
- `src/host/launcher/test/native-*.tsx` — stubs whose exports must mirror the libraries' APIs.
- The 9 `checks/test/{release,repo}` suites that read native source.

## Risks and unknowns
- I did not verify RN 0.88.1's requirements (JDK, Gradle, AGP, Kotlin, NDK, iOS minimum, CocoaPods, Node) or library compatibility with 0.88; all of that is outside the repo.
- I did not verify whether 0.88's Hermes ships `TextDecoder` or a streaming fetch `Response.body`; either would silently change the polyfill and transport branches.
- I did not verify that the swizzled iOS selectors/classes and `ReactModalHostView.dialog`/`NativeDeviceInfoSpec` still exist in 0.88; only the iOS status-bar code reports a missing symbol at runtime.
- I did not verify how `npm test`/jest is configured (no root jest.config.js) or whether `@react-native/new-app-screen` is still imported anywhere.
- Stale build output under `android/app/build`, `android/.gradle`, `ios/build` is on disk.
- The `org.gradle.java.home` path is machine-absolute.
