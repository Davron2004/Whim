# RN 0.85.3 -> 0.88.1 upstream research (as of 2026-11-20)

Sources: B86/B87/B88 = reactnative.dev/blog/2026/06/11/react-native-0.86, /2026/08/11/react-native-0.87, /2026/10/19/react-native-0.88.
CL = https://github.com/react/react-native/blob/main/CHANGELOG.md. NPM = `npm view` today. TPL = https://github.com/react-native-community/template (tags 0.85.3, 0.88.1, diffed locally). TGZ = `npm pack react-native@0.85.3/0.88.1` contents.

## 1. Breaking changes per release
**0.86 (2026-06-11)** - "no user-facing breaking changes" (B86). Repo moved facebook -> react org. Edge-to-edge fixes on Android 15+. Metro ^0.84.2. Deprecated `ViewUtil.getUIManagerType`. `ExceptionsManager.reportErrorsAsExceptions`: only literal `false` opts out. Android: WebSocket `Cookie` header no longer stripped; Blob content provider now works on new arch; OOM catch in NetworkingModule (B86/CL). JSI gains TypedArray/ArrayBuffer helpers.
**0.87 (2026-08-11)** - the breaking one (B87):
- Strict TypeScript API is default; deep imports (`react-native/Libraries/*`, `src/private/*`) are TS errors; opt-out `customConditions: ["react-native","react-native-legacy-deep-imports"]` lasts "through 0.88" only. `*Properties` aliases removed.
- Removed: `InteractionManager`, `Modal.animated`, StatusBar `backgroundColor/translucent/networkActivityIndicatorVisible` + setters, boolean `keyboardShouldPersistTaps`, `useTurboModules` flag (TurboModules always on), `NativeDialogManagerAndroid`, `Touchable` root export, `NativeMethods` types, `rn-get-polyfills` (use `@react-native/js-polyfills`), connecting standalone `react-devtools` over WebSocket, YAML/`.es6` Metro configs. `useColorScheme()` can return null, never 'unspecified'. `@react-native/jest-preset` must be consumed as a package (CL v0.87.0).
- Hermes: legacy Hermes removed from C++; `hermesV1Enabled` (Gradle) and `RCT_HERMES_V1_ENABLED` (CocoaPods) removed (CL 0.87.0). Hermes V1 was already default in 0.85: TGZ 0.85.3 podspec uses V1 unless `RCT_HERMES_V1_ENABLED=0`. So no engine switch 0.85->0.88; it just loses the opt-out. Default babel transform profile becomes `hermes-stable` (CL 0.87.0).
- Metro 0.84 -> 0.87 (B87). Node >= 22.13.0. Kotlin >= 2.0 (bundled 2.2.0). minCompileSdk 34; compileSdk/buildTools 37. First AGP 9 support; recommended opt-out `android.builtInKotlin=false` + `android.newDsl=false` (removed from AGP 10).
- iOS: experimental SwiftPM (CocoaPods remains default); new header-only xcframeworks - bare `#import <RCTAppDelegate.h>` must become `<React/RCTAppDelegate.h>`.
- Deprecated: `InitializeCore` path, `ImageBackground`, `Appearance.setColorScheme('unspecified')`, `DrawerLayoutAndroid`, `UIBlock`, iOS `TimingModule`.
**0.88 (2026-10-19; 0.88.0 npm 2026-10-15, 0.88.1 2026-10-27)** - "no user-facing breaking changes" (B88), but:
- React 19.3.0 (peer `^19.3.0` - NPM; react 19.3.1 is npm latest). Hermes `260318099.0.4` in blog; 0.88.1 depends on hermes-compiler `260318099.0.5` (NPM). Metro 0.87 (min 0.87.1).
- Web-based event dispatching via W3C EventTarget is now default (B88). Props/synthetic events/touch responder unchanged; risk only for code touching RN event-plugin internals. Legacy path kept behind internal flag, to be removed.
- iOS SceneDelegate: "Starting with the iOS 27 SDK, Apple requires the UIScene lifecycle: UIKit apps built with Xcode 27 will fail to launch" (B88). Additive; AppDelegate path still supported. Single scene only. 0.88.1 also fixes StatusBar on iOS 27 when `UIViewControllerBasedStatusBarAppearance=YES` (CL 0.88.1).
- Android default `User-Agent` now includes app name+version (B88). Blob/FileReader/XHR spec fixes: `FileReader` throws `InvalidStateError` on overlapping reads; `XMLHttpRequest.setRequestHeader` appends duplicates (CL 0.88.0).
- Deprecated: `InputAccessoryView` (iOS), prefixed `experimental_background*` styles, `ReactFragment.fabricEnabled`. `RCT_REMOVE_LEGACY_MODULE_INTEROP`/`..._COMPONENT_INTEROP` opt-ins exist, default off.
- SwiftPM rollout: 0.87 experimental, 0.88 hardened, 0.89 planned default with CocoaPods opt-out (B88).
**fetch / streaming**: No change. TGZ 0.88.1 `Libraries/Network/fetch.js` still `require('whatwg-fetch')` (XHR-based, no `Response.body`); no ReadableStream in `Libraries/Network` or `src/`. facebook/react-native issue #27741 "fetch does not support streams" is still open (`gh api` search). Streaming still requires XHR incremental reads.
**console/logging**: no console change found in blogs/CL for 0.86-0.88 (grep of CL). Only DevTools additions (WebSocket Network panel on Canary, screenshots).
**TextDecoder/TextEncoder**: RN JS (`Libraries`, `src`) in both 0.85.3 and 0.88.1 tarballs has zero references, so RN core ships no polyfill and 0.88 adds none. Whether Hermes V1 260318099 exposes a native `TextDecoder`: unverified (open RN PRs #56325/#56326 add TS types for them, suggesting still untyped in RN).
**Node**: engines 0.85.3 `^20.19.4||^22.13.0||^24.3.0||>=25` -> 0.88.1 `^22.13.0||^24.3.0||>=26.0.0` (NPM). Node 25 and 22.11/22.12 are no longer in range.
**React**: 0.85.3 `^19.2.3` -> 0.88.1 `^19.3.0` (NPM). `react-dom` is not an RN dep; `react-test-renderer@19.3.0` exists (template pins it).

- iOS: `min_ios_version_supported` 15.1 unchanged; min Xcode 16.1 unchanged (TGZ `scripts/cocoapods/helpers.rb`). Podfile unchanged (still CocoaPods). New `SceneDelegate.swift` (extends `RCTDefaultReactNativeFactoryDelegate`, calls `startReactNative(withModuleName:in:connectionOptions:)`, forwards URL/user-activity to `RCTLinkingManager`); `AppDelegate.swift` shrinks to `return true`; Info.plist adds `UIApplicationSceneManifest` (SceneDelegate class `$(PRODUCT_MODULE_NAME).SceneDelegate`, multiple scenes false), `RCTNewArchEnabled=true`, `UIViewControllerBasedStatusBarAppearance` false -> true; pbxproj adds SceneDelegate.swift.
- Template package.json: react 19.3.0, RN 0.88.1, `@react-native-community/cli` + platform packages **20.2.0** (CLI 20.2.0, 2026-06-25), typescript ^6.0.3, `tsconfig` drops `types:["jest"]`, `engines.node >= 22.11.0` (template unchanged; RN itself requires 22.13). - All `@react-native/*` tooling packages are at 0.88.1 on npm and must move in lockstep: babel-preset, metro-config (peer of community-cli-plugin), eslint-config (peers eslint ^8||^9, prettier >=2), typescript-config, jest-preset (peer react ^19.2.3), new-app-screen (peer RN exactly 0.88.1).

## 4. Known regressions / open issues in 0.88.x
- 0.88.1 is the newest stable; `0.88-stable` is 1 commit ahead of v0.88.1 (`gh api compare`), no 0.88.2 tag yet (24 days after 0.88.1). 0.89.0-rc.2 published 2026-11-18. Pending 0.88 cherry-picks (reactwg/react-native-releases issues #1541, #1532, #1544, #1491, #1540, #1538, #1490, #1505): iOS `NativeDeviceInfo.getConstants` data race crash (#60014, closed upstream), Hermes source extraction repo-agnostic (#1491), lazy ViewManager init in UIManager, Android 15+ text line breaking, iOS renderer scheduler teardown, responder events for unmounted components, zero-sized recycled view assertions. 0.88.x patch cadence therefore still active but slow.
- Open issues (github.com/react/react-native, all low reaction counts, none labeled showstopper): #59354 recycled iOS `InputAccessoryView` blocks touches (0.88 regression); #59926 iOS `RCTNetworkTask` EXC_BAD_ACCESS when Image load cancelled; #59741 stale Yoga flex-basis (fixed width -> flex:1); #60140 iOS recycled `RCTViewComponentView` child ordering; #59853 `@react-native/babel-preset` fails on class static blocks; #59649 published types reference `src/types/globals.d.ts` conflicting with DOM lib under `skipLibCheck:false`; #59772 prebuilt iOS frameworks unstripped (+9.3 MB); #59927/#60090 iOS Dynamic Type live change not re-laying out text; #59519 (closed) taps lost after view unmounts during touch with native event-target dispatching; #60091 assets-registry ESM issue for non-Metro web bundles.

## 5. WebView message / sub-frame behavior
- Nothing in 0.86-0.88 touches WebViews (RN core has no WebView; blogs/CL grep). 0.88 event dispatching change applies to RN host views, not WebView message events.
- react-native-webview Android (13.16.1 local, 14.0.1 and 17.1.0 tarballs; identical logic): `RNCWebView.createRNCWebViewBridge` uses `WebViewCompat.addWebMessageListener(webView, "ReactNativeWebView", Set.of("*"), listener)` when `WEB_MESSAGE_LISTENER` is supported, else `addJavascriptInterface`. The listener signature receives `isMainFrame` but ignores it: `onPostMessage(view, message, sourceOrigin, isMainFrame, replyProxy)` -> `onMessage(message.getData(), sourceOrigin.toString())`. The JS `onMessage` event therefore carries `data` and `url` (= source origin string) but no frame flag, so sub-frame vs main-frame messages are distinguishable only by origin/url, and an opaque (sandboxed) origin's string form is unverified. The `*` origin rule injects `window.ReactNativeWebView` into every frame, including iframes. 17.1.0 is the same except `injectJavascriptObject` was removed from this method.
- iOS (same three versions): messaging user scripts are `forMainFrameOnly:YES` (hard-coded; the `injectedJavaScript*ForMainFrameOnly` props only govern injected JS), so `window.webkit.messageHandlers.ReactNativeWebView` is only installed in the main frame; `didReceiveScriptMessage` reports `message.frameInfo.request.URL` as `url` and does not expose `frameInfo.isMainFrame`.
- Net: through 17.1.0 there is no public API in react-native-webview that exposes `isMainFrame`; any such distinction on Android needs a patch/fork of `RNCWebView.java`.

## Highest-risk items (ranked)
1. Reanimated 4.6.0 + worklets 0.12.2 are outside 0.88 peer ranges (`0.83-0.87`); must move to 4.7.x/0.13.x (RN 0.86-0.88) or 4.8.x/0.14.x (0.87-0.89). Native codegen/JSI-sensitive.
2. Android toolchain jump: AGP 8.12 -> 9.2.1, Gradle 9.3.1 -> 9.4.1, Kotlin 2.2.0, compileSdk/buildTools 37 (SDK 37 packages must be installed), plus the `builtInKotlin=false`/`newDsl=false` opt-outs; every native library's Gradle script is an AGP 9 risk (JDK 21 itself is fine).
3. iOS with Xcode 27: UIScene lifecycle is required (SceneDelegate + Info.plist manifest + pbxproj entry); `UIViewControllerBasedStatusBarAppearance` semantics changed; Xcode 27 + iOS 27 SDK issues (status bar, screens 4.30 iOS 27 layout changes).
4. Node/React minimums: Node must be >= 22.13 (repo declares >= 22.11), React 19.3.0 exact peer, all `@react-native/*` at 0.88.1; Strict TS API default (deep imports now type errors; TS 6 in template) and removed APIs (`InteractionManager`, StatusBar props, `rn-get-polyfills`, etc.).
5. Native-module churn: op-sqlite ^16.2.0 and mmkv/nitro have no stated 0.88 support (nitro 0.35.9 -> 0.37.x recommended for 0.88 build); react-native-webview latest tag 14.0.1 vs `next` 17.x with New-Arch-only; `isMainFrame` not surfaced in any version. fetch still has no streaming `response.body`, no TextDecoder polyfill in RN core; 0.88.x has no patch release past 0.88.1 and known iOS crashes await 0.88.2.
