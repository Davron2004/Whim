## Current behavior
**#145 `credit`.** Firestore `credit` is one non-transactional `usage/{firestoreKey(deviceId)}` `set(..., {merge:true})` with `FieldValue.increment` on prompt/completion/total tokens plus `lastCreditedDay` (design D2, file header). Signature is `(deviceId, usage)` only; no request or admission id reaches the store. `admit` mints `randomUUID()` per call and runs `db.runTransaction` (`maxAttempts: 25`): `tx.getAll` reads `requests/{requestId}` and the counters; if the existing row's `admissionId` equals this call's own id it returns `ok` before the limit checks (lost-reply recognition); otherwise `tx.create` writes the row and `shiftCounters(+1)`; a reused foreign request id throws. Documents: `usage/{deviceId}` (lifetime totals + `lastCreditedDay`); `requests/{requestId}` (deviceId, kind, utcDay, startedAt, endedAt, outcome, failureReason, tokens, costUsd, costState, generationIds[], refunded, optional `admissionId`); `admission/{utcDay}:{kind}:{deviceId}` and `admission/{utcDay}:global:{kind}` (count, utcDay, kind, deviceId).
`credit` call sites (all pass only `deviceId` + `Usage`): generate.ts l.359 (policy unavailable, free slot), l.369 (policy verdict), l.407/l.415 (line), l.551 (in-stream `usage` event via `forwardEvents`, l.748); clarify.ts l.356, l.389, l.593; rewrite.ts l.202; resolve.ts l.257 (uncredited usage — its `creditOwned` flag, a boolean or set of generation ids, is the existing double-credit guard). SQLite `credit` is a synchronous atomic `INSERT ... ON CONFLICT DO UPDATE`; in-memory is a map add; neither has an idempotency key.
Conformance: `store-conformance.suite.ts` `creditIncrements` (l.304-321, incl. 5 concurrent credits), a `credit('')` case (l.536), a failure-injection entry (l.734); runs under SQLite in `server:test` and for Firestore in `firestore-conformance.ts`, whose `losingCommitReplies(db)` (l.195-222) re-runs transactions after commit (simulated lost reply) with `lostCommitReplyTest` for `admit` — nothing equivalent for `credit`. Emulator: `npm run stores:firestore:test` = pinned `firebase-tools@15.32.1` `emulators:exec` on `demo-whim-conformance` running `server/test/firestore.run.mjs` (Java 21; refuses without `FIRESTORE_EMULATOR_HOST`; 60 s watchdog; fresh `conformance/<runId>-<n>` namespace per open). `firestore-index-coverage.ts` checks sent queries against `deploy/firestore/indexes.json`.

**#119/#120 content policy and the line.** `ModelContentPolicy.check` (policy.ts:137) combines `AbortSignal.timeout(policyTimeoutMs)` with the request signal; `WHIM_POLICY_TIMEOUT_MS` default 10000 (config.ts:351); maxTokens 48, `reasoning: 'off'`, rewrite model. No retry in the policy; a grep of `openrouter.ts` for retry/attempt found nothing. Timeout, transport error, unparsable output or an out-of-set verdict collapse to `PolicyUnavailableError` (policy.ts:28, optional `usage`/`generationId`); routes answer `503 policy_unavailable`. The check runs on clarify, rewrite and generate (route name only for logs); cache key = SHA-256 of canonical input. `cachedPolicy`: in-memory LRU+TTL (1000 entries, 15 min), verdicts only, and the only emitter of the "content policy check" log line (`route`, `verdict` incl. `cached-*`/`unavailable`, `category`, `durationMs`). A real classifier call is credited via `usageStore.credit`; cost resolves via `resolveRequestUsage(requestId, deviceId, ids, creditOwned, deps)`.
Unary (clarify/rewrite): `admit` first (device unit, then global), then policy. Unavailable → credit, settle `unavailable`/`policy_unavailable`, refund, release, resolve cost. Refuse → settle `refused`/`content_policy`, no refund. Generate free slot (`admitWithSlot`, l.335): same as unary. Generate busy slot (`admitIntoLine`, l.390): `unitAvailable` (no write), then `checkPolicy`, no ledger row. Unavailable → only `credit` + `ticket.leave()`; no row, cost has nowhere to land (tokens resolved via the `requestId ''` sentinel). Refuse → `recordLineRefusal` does admit, settle `refused`, refund in `finally`. This is the asymmetry.
The line: `slots.acquireInLine(deviceId)` refuses on drain, `device_busy`, or a full line (`WHIM_QUEUE_MAX` 50); wait bounded by `WHIM_QUEUE_MAX_WAIT_MS` (180000); `WHIM_MAX_CONCURRENT_GENERATIONS` 3; `checkCredit` runs before it. Limits: generations/device/day 15, generations/day 400, clarify/device/day 60, rewrite/device/day 60, unary/day 2000, concurrent unary 16, beta 10/client/hour and 2000/day. The only per-IP-like limiter is `/beta/signup` (`waitlist/limiter.ts`, salted hash of `x-forwarded-for`, in memory); `/v1` has none. Cloud Run deploy forwards only `WHIM_BETA_LIMIT_*` via `server_optional_keys`.

**#139 boot.** `startServer`: config → preflight → model → stores → (non-stub) `SynthRunSession.launch({concurrency})` → `runBootSelfTest` → listener. A failed launch rejects `SessionError('browser_launch_failed')` → `BootError('browser_launch')` → fatal `boot failed` + exit 1; no retry at boot ("no retry with weaker options"). After `browser_disconnected`, the next run relaunches through the single mutexed call site `startBrowser`; a failed launch is forgotten. `browserLaunchOptions()`: headless, `chromiumSandbox:true`, proxy to closed `127.0.0.1:9` with `<-loopback>`, `--host-resolver-rules=MAP * ~NOTFOUND`, WebRTC non-proxied UDP disabled, DNS prefetch off; `synthrun/test/isolation.ts` scans for other launch calls. **#143/#134 load test.** `deploy/loadtest/run.sh start|drive|stop` swaps the VM compose service for a replay-model image; CPU sampled over SSH with `docker stats` every `WHIM_LOADTEST_SAMPLE_INTERVAL_S` (a readonly constant `=2` at run.sh:26). ## Constraints and invariants
- Decisions #71/#72/#73: Cloud Run `us-east4`, data in Montreal; one instance cap; stores in Firestore.
- The four capability specs are absent from `openspec/specs/`; they exist only as deltas in unarchived changes (`public-generation-server`, `beta-1`, `durable-server-stores`). MODIFIED headers must match those deltas exactly.
- Ledger is content-free; failure reasons validate against closed sets (`assertFailureReason`, `failure-codes.ts`). Policy log lines carry no checked text.
- Chromium launch config has one call site and may never be weakened (`synthrun/test/isolation.ts`).
- `server/test` bundles under esbuild Node and cannot import RN; tests import store submodules, not barrels.
