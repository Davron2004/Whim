## Why

The parent change (`harden-synthrun-binding-isolation`, archived) fixed one instance of a class: a Playwright host binding exposed via `exposeFunction`, which installs on the global of every execution context — including the opaque-origin sandboxed iframe — and discards the `{context,page,frame}` source. One live instance remains: `invariants/sandbox-isolation/bridge/runner.mjs:72`, inside the never-regress containment suite itself. A hostile bundle can call `globalThis.whimHostDispatch(...)` directly, get an authoritative sysret from the real gate wired to a real `:memory:` engine (`host-shim.ts:48-49,73-79`), and paint exactly the text scenario 1 (`runner.mjs:88-101`) greps for — so this is not a product bug, it is a verification-code bug that makes a green check lie, the specific failure decision #28 exists to prevent. Per `research.md`'s "How the research primitive failed across three runs", the research primitive that reads code for exemplars — not verdicts — let this exact line survive three separate research passes, so closing the instance without repairing the primitive leaves the next instance equally likely to be missed.

## What Changes

- **A — the detector (Class-1, dispatchable).** A structural AST check under `checks/`, reaching the fast gate through the existing `checks:test` step (`scripts/gate.sh:63` → `node checks/test/run.mjs`) with NO edit to `scripts/gate.sh`. Rule, over every file importing `playwright`: `exposeFunction` is banned outright, no allowlist; every `exposeBinding` callback must open with a main-frame provenance rejection as its FIRST statement. Must cover `.mjs` and `.ts`, and must cover directories ESLint ignores (`.eslintignore` excludes `invariants/`, which is exactly where the live bug is). Non-vacuity is mandatory and splits in two. The *unguarded* case is proven against the pinned pre-fix commit 754e2f7, where the detector must flag runner.mjs:72 — a red-check against a real bug rather than a synthetic one, reproducible by anyone at any time rather than dependent on transient tree state. The *weakened* case is not, and it is the discriminating variant: no real instance exists of an `exposeBinding` whose guard is present but not first, so without a synthetic fixture the "first statement" half of the rule ships untested. That fixture is required — as inline source strings the detector parses, paired with a correctly-guarded control that must NOT be flagged.
- **B — close the hole (HUMAN-BOOTSTRAP, `invariants/`).** Convert `runner.mjs:72` to `exposeBinding` with a first-statement main-frame guard returning `null`, add a refusal counter surfaced on the object `scenario()` returns (a silent `null` is indistinguishable from a no-op, which is why the counter is required), and add an adversarial scenario asserting refusal, absence of the attempted write **read back from the engine** rather than from a trace, and a positive control that the legitimate main-frame path still succeeds.
- **C — repair the research primitive (HUMAN-BOOTSTRAP, `.claude/**` + schema).** Amend `.claude/agents/researcher.md` so that during a hardening change an in-repo occurrence of the pattern under investigation is a SUSPECT, not an exemplar — citing one for any property (exposure scope, shape, naming, wiring) requires stating whether it satisfies the property being hardened, or marking it NOT-CHECKED. Amend the `whim-harness` schema's `research` artifact instruction to require a **pattern census** (enumerate every in-repo occurrence, classify each SAFE / UNSAFE / NOT-CHECKED, name the test applied), replacing "find an exemplar to copy" as a research primitive. Amend `.claude/commands/opsx/apply.md` (near its step-13 closing duties at `:57`) plus the schema so that any census row marked UNSAFE and out of the current change's scope MUST be written to `openspec/critic/open-follow-ups.md` with file:line and vulnerability class — report prose is not sufficient.

**Why C is the structural fix, not a discipline reminder.** "Find an exemplar" and "enumerate every occurrence" return the *same hits*, but only the second forces a verdict per row. A census cannot emit "cited the vulnerable line as the good example" — that line's row would have to read UNSAFE. The actual failure mechanism (research.md, "How the research primitive failed across three runs"): a wrong comparison axis (`page.` vs `context.` exposure scope) while the same document had already established that `exposeFunction` discards the source, compounded by an "owner-authored / out-of-scope" classification (decision #28) applied before the soundness question was asked.

**Ordering constraint.** Workstream B is applied by a human FIRST; workstream A's detector chain is dispatched afterwards, against an already-patched tree, and self-gates green. The reverse order is not permissible — a detector designed to red the gate can never pass its own self-gate in the chain-dispatch loop. The pre-fix red-check is captured against the pinned commit 754e2f7, not against live tree state.

## Capabilities

### New Capabilities
- `hardening-research-discipline`: the process requirements a hardening change's research artifact must satisfy (workstream C) — a pattern census classifying every in-repo occurrence of the pattern under investigation, and a mandated durable sink in `openspec/critic/open-follow-ups.md` for UNSAFE rows that fall outside the current change's scope. Created as a new capability because no existing one owns proposal/research *content* requirements: `gate-preconditions` is scoped to the harness's own multi-step-state-change verification, `sonar-recurrence-tracking` is SonarCloud-specific, and `static-checks` is scoped to candidate mini-app bundle source rather than repo or process artifacts.

### Modified Capabilities
- `capability-bridge`: adds three new requirements to the existing capability (workstream A/B) — host functions exposed to a Playwright page must use `exposeBinding` with a first-statement main-frame provenance rejection, the bridge-invariants suite must prove syscall authority against a hostile caller in the sandboxed frame, and the fast gate must statically reject a violating call site. This is the capability that owns the `bridge:invariants` suite where the live instance sits.

## Impact

- **Code:** new `checks/` module + fixtures (Class-1); `invariants/sandbox-isolation/bridge/runner.mjs` (HUMAN-BOOTSTRAP); `.claude/agents/researcher.md`, `.claude/commands/opsx/apply.md`, `openspec/schemas/whim-harness/schema.yaml` (HUMAN-BOOTSTRAP, `.claude/**` + schema are protected paths); `docs/capabilities.md` (Class-1, unprotected).
- **Gate:** `scripts/gate.sh` itself is untouched — the new check reaches the fast gate only through the existing `checks:test` step.
- **Process:** future `research.md` artifacts must contain a pattern census, and any UNSAFE/out-of-scope row must land in `openspec/critic/open-follow-ups.md`.

**Non-goals, decided explicitly:**
- No ESLint rule — `.eslintignore` excludes `invariants/` by design (adversarial fixtures reach for forbidden globals on purpose), so an ESLint rule provably cannot see the one vulnerable file and would create false assurance.
- No shared `exposeMainFrameBinding(target, name, cb)` helper — it would have to live in an agent-editable location, making an agent-editable module load-bearing for Class-2 verification code; three inline two-line guards plus a structural check that verifies the guard's shape has no such trust inversion. Cost accepted: three near-identical guards.
- No name scrub / `delete globalThis.whimHostDispatch` — the binding is unscopeable and re-mintable via `__playwright__binding__controller__`; a scrub is defence in depth at best, never the guarantee.
- No change to `build/assemble.mjs` — the outer-page gating this relies on already exists there (`:121`, `:143`).
- No widening of the CSP or any containment leg; no change to the nonce-authenticated-verdict rule — frame provenance is an ADDITIONAL necessary condition, never a replacement.
- Not fixed here, recorded as an observation: `scripts/gate.sh` is Class-2 protected but the suites it invokes (including `checks:test`) are not, so an agent could weaken a detector the gate depends on. Pre-existing, true of every Node suite in the gate, consistent with the current trust model.
