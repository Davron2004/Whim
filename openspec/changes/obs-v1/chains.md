## chain-B: logging seam

- tasks: B1, B2, B3, B4, B5, B6, B7
- rationale: The channel registry, the logger, redaction, the ring buffer and the batching sink are
  one rule set — split across implementers, "what counts as sensitive" and "what a record looks
  like" diverge, and the overlay and the sink then disagree about the same record, which is exactly
  the failure design D3 exists to prevent. The type-only contract module rides here because it is
  the record's shape, and the shape has one author. Nothing downstream can start without this
  chain's exported surface.
- reads: `specs/host-observability/spec.md` §"One logging seam; `console.*` is not a device log
  surface", §"Every log record is a structured event held in a bounded ring buffer", §"Sensitive
  fields are structurally unloggable on the device", §"Batched delivery to the dev sink is
  best-effort and never affects the app"; `specs/generation-contract/spec.md` §"The dev log envelope
  is a type-only contract module" + the modified §"Shared wire-contract package"; `design.md` §D2,
  §D3, §D4, §D5, §D6. handoff: `handoff/deps-and-lint.md`
- writes-contract: `handoff/logging-seam.md` — the logger's exported signatures, the level set in
  order, the channel constants verbatim, the record and batch types verbatim (as declared in
  `contract/src/dev-log.ts`), the sink route path both sides implement, the ring buffer's snapshot
  accessor and its capacity constant, the redaction marker and the sensitive-field-name set, the
  sink's enable flag, and what a sink failure does and does not do.
- after: chain-A
- owns: `src/host/logging/**`, `contract/src/dev-log.ts`,
  `src/host/logging/test/logging.suite.ts`, and the registration line it adds to
  `src/host/launcher/test/acceptance.ts`
