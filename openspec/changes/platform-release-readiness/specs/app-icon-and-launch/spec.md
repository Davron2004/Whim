## ADDED Requirements

### Requirement: One command derives every icon and launch asset from one source
Every app icon, launch asset and store listing image on both platforms SHALL be generated by one release-tooling command from one foreground mark (`release/assets/icon-foreground.svg` or `.png`, square, transparent background) and the colors in `release/assets/brand.json`.
The outputs are the iOS app icon, the iOS launch mark image set and launch background color set, the Android adaptive icon layers (foreground, monochrome, background color), the Android legacy square and round icons at every density, the Play hi-res icon and the Play feature graphic. The command SHALL write `release/assets/generated.json`, recording the SHA-256 of the source, of `brand.json` and of every output. Exactly one foreground source file SHALL exist.

#### Scenario: Replacing the artwork
- **WHEN** a designer replaces the foreground mark with new artwork and runs the generate command
- **THEN** every output on both platforms and both listings is rewritten from it and `generated.json` records the new hashes, with no icon edited by hand

### Requirement: The checks detect stale, missing or mis-sized assets
The release checks SHALL fail when any output listed in `generated.json` is missing, when an output's pixel size differs from its required size, or when the hash recorded for an output, the source or `brand.json` no longer matches the file on disk. Each failure SHALL name the file.

#### Scenario: Source edited without regenerating
- **WHEN** the foreground mark changes and the generate command isn't run
- **THEN** the release checks fail, naming the source file and telling the developer to run the generate command

#### Scenario: A deleted density
- **WHEN** `android/app/src/main/res/mipmap-xxhdpi/ic_launcher.png` is deleted
- **THEN** the release checks fail, naming that path

### Requirement: Store-facing icons meet each store's format rules
The iOS app icon SHALL be one 1024×1024 PNG with no alpha channel, referenced as a single-size icon from the `AppIcon` set.
The Play hi-res icon SHALL be a 512×512 PNG, and the Play feature graphic a 1024×500 PNG with no alpha channel. The generator SHALL composite the mark over the brand background wherever the target format forbids transparency.

#### Scenario: An alpha channel is caught before upload
- **WHEN** the iOS icon file carries an alpha channel
- **THEN** the release checks fail, naming the file, before any build or upload runs

### Requirement: The Android icon is adaptive with a legacy fallback
The Android app SHALL declare `ic_launcher` and `ic_launcher_round` as adaptive icons (background color, foreground and monochrome layers) for API 26 and later, and SHALL ship legacy square and round PNG icons at mdpi, hdpi, xhdpi, xxhdpi and xxxhdpi for older devices.
The foreground layer SHALL keep the mark inside the adaptive icon's central safe zone.

#### Scenario: A themed icon on Android 13
- **WHEN** the user turns on themed icons on an Android 13 device
- **THEN** the launcher shows Whim's monochrome layer instead of a generic fallback

### Requirement: Launch shows the mark on the shell paper color with no flash
Both apps SHALL show the foreground mark centered on the launch background color while launching, and SHALL keep that color as the root background until the launcher draws its first frame.
The launch background SHALL equal the shell's paper color, `SHELL_COLORS.paper`, and the release checks SHALL fail when `brand.json` disagrees with it. Android SHALL do this without a new dependency.

#### Scenario: Cold start has no color jump
- **WHEN** the user cold-starts either app
- **THEN** the screen goes from the launch mark on paper straight to the launcher's first frame, with no white or black frame between

#### Scenario: Brand color drifts from the shell
- **WHEN** `brand.json` sets the launch background to `#ffffff` while `SHELL_COLORS.paper` is `#fbfaf8`
- **THEN** the release checks fail, showing both values
