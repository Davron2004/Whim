## Why

Whim has to reach TestFlight and the Play closed-testing track this week, and neither app can be shipped as it stands. Both still carry the template id `com.whim`. The iOS project has no team, no entitlements and no icon. Android release builds are debug-signed and debuggable, and every build type allows cleartext to dev hosts (research.md A). Two latent crashes and a silent platform wait on top: a module-scope `new TextDecoder()` aborts any path that reaches the storage engine before the version store, `process.platform` reads `'android'` on iOS, and iOS plays no sound cues (research.md B). None of it is in a script, so every release would be a hand-run ritual.

## What Changes

- **One native release file.** `release/whim-release.xcconfig` declares the app id, Apple team id, marketing version, development build number and release domain. The Xcode project reads it as its project-level base configuration and Gradle parses it, so no native file repeats those literals. A suite keeps its domain equal to the launcher's `WHIM_DOMAIN`.
- **Identity and signing.** `com.anycognition.whim` on both platforms, team `2B7K4YLS34` with automatic signing on iOS, and a Play upload key read from outside the repo. The Kotlin namespace stays `com.whim`.
- **BREAKING (dev workflow): Android build types.** `release` becomes the store build: upload-signed (it fails with a named cause when the key isn't configured), not debuggable, no cleartext, shipped as an AAB. A new `offline` build type takes over the old emulator role (embedded bundle, debug-signed, debuggable, dev cleartext hosts), and `npm run android:release` is repointed to it, so every existing doc and demo recipe keeps working.
- **Versioning.** One marketing version for both platforms. Each release run computes one build number for both builds, as whole minutes since 2026-01-01T00:00Z, and refuses it if the store already has one at least as high.
- **Platform hardening.** iOS gets `ITSAppUsesNonExemptEncryption = false`, iPhone only, portrait, no empty usage strings, and a privacy manifest covering the required-reason APIs of the linked native code plus the collected data types. Android dev cleartext hosts move to the debug and `offline` source sets.
- **App link delivery** per store-launch-compliance D17: the associated-domains entitlement and `RCTLinkingManager` forwarding on iOS, and a verified `https://whim.<domain>/a/` intent filter on Android. Both hosts come from the native release file. A command prints the exact AASA and assetlinks files for ops.
- **Icons and launch screens** generated by script from one foreground mark and a background color: an opaque single-size iOS icon, Android adaptive, legacy and round icons, the Play icon and feature graphic, and launch screens on the shell's paper color with no flash before the first frame. A placeholder mark ships until real artwork arrives.
- **iOS `WhimTone`.** An Objective-C++ TurboModule that plays the same three tones as Android, registered through `codegenConfig.ios.modulesProvider` (a HUMAN-BOOTSTRAP `package.json` edit).
- **Hermes prerequisites.** The polyfills move to `src/host/platform/`. `index.js` installs them, with the real `Platform.OS`, before any other module evaluates, and the storage engine imports them too.
- **Release pipeline.** fastlane lanes build, sign and upload to TestFlight and the Play closed-testing track and push listing metadata. A TypeScript preflight (toolchain, credential files, placeholder domain, metadata, build number, signer fingerprint, privacy audit) runs first and fails with the exact cause. Every run is attended; nothing runs in the gate or CI.
- **Store listing as files.** App Store and Play text in fastlane's directory layouts, age rating, App Privacy and Data safety answers, all checked for field limits, domain literals, puffery and privacy consistency. URLs and the review contact are filled in at upload time, never committed.
- **Runbook.** `docs/release/mobile.md`, plus updates to the Android build notes in CLAUDE.md and README.md.

## Capabilities

### New Capabilities
- `native-release-config`: the native build-time configuration file and what it drives. Covers identity, signing, versioning, the store and dev build types, cleartext policy, the iOS plist and entitlement surface, the privacy manifest, and domain lockstep with the launcher.
- `hermes-runtime-prerequisites`: the app entry installs Hermes polyfills before anything else evaluates, reports the real platform, and never overwrites a native global.
- `app-icon-and-launch`: every icon and launch asset on both platforms and both stores is derived by script from one source, stays in sync with it, and launches without a color flash.
- `store-listing`: listing text, age rating and privacy answers live as validated files, consistent with each other, with the privacy manifest, and with the consent disclosure.
- `store-release-pipeline`: attended, scripted build, sign and upload to TestFlight and the Play closed-testing track, gated by a preflight that names what's wrong.

### Modified Capabilities
- `mini-app-cues`: sound cues play on iOS from the same tone table as Android, and the pour-over on-device acceptance covers a real iPhone too.
- `app-links`: the capability introduced by `store-launch-compliance`, which applies before this change. It gains the native delivery requirements, the iOS entitlement and forwarding and the Android verified filter, plus exact association-file content.

## Impact

- **iOS:** `ios/Whim.xcodeproj/project.pbxproj`, `ios/Whim/{Info.plist,PrivacyInfo.xcprivacy,AppDelegate.swift,LaunchScreen.storyboard}`, a new `Whim.entitlements`, a new `WhimToneModule.mm`, and `Images.xcassets` (AppIcon, LaunchMark, LaunchBackground). `ios/Podfile.lock` changes only if `pod install` output changes.
- **Android:** `android/app/build.gradle`, `AndroidManifest.xml`, `res/xml/network_security_config.xml` plus a new `src/debug/res/xml/` copy, `res/values*/` styles and colors, `res/mipmap-*`, `res/drawable*`, `MainActivity.kt`.
- **JS:** `index.js`, new `src/host/platform/`, the three version-store importers, `src/host/storage-engine/marshal.ts`, and comments in `cue-backend.ts` and `NativeWhimTone.ts`. No launcher file.
- **New trees:** `release/` (native config, brand assets, store content), `scripts/release/` (TypeScript CLI run through an esbuild runner), `fastlane/`, `checks/test/release/`, `docs/release/mobile.md`.
- **Protected files:** `package.json` (`codegenConfig.ios` and the `android:release` script) is HUMAN-BOOTSTRAP. No gate, harness, lint, knip or tsconfig edit.
- **Dependencies:** no npm or Gemfile change. fastlane comes from Homebrew with a minimum version the preflight checks. Playwright, already a root devDependency, renders icons.
- **Other tooling:** the Maestro flows in `demo/android/flows/tea/` change `appId`. Existing `com.whim` dev installs become a separate app.
- **Accounts (attended):** an App Store Connect app record and API key, a Play Console app with Play App Signing and one manual first upload, the upload keystore, and device checks on the paired iPhone 16 Pro Max.
- **Follow-up, not in this change:** the iOS launcher UI fixes (settings glyph, back navigation, safe-area paddings, tile a11y labels) and iOS haptics (design.md).
