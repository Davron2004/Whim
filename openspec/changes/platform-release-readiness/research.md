## Constraints and invariants
- mini-app-cues: closed token sets resolved host-side; fire-and-forget, at-most-once; rows bind to an injected backend; a missing backend is a structured error, never a throw (B).
- #36 D2 / #39: polyfills must be in place before isomorphic-git runs; "imported first", not "imported somewhere" (B).
- `package.json` sits in gate.sh's `CONFIG_SET` tripwire, so any edit is HUMAN-BOOTSTRAP (C).
- No decision or live spec covers native packaging, signing, entitlements, icons or deep links (A, C). Compliance chains.md:5 declares native projects out of its scope (C).

## E. Native network deny terrain (planner amendment, 2026-09-14)
<!-- Source: docs/security/2026-09-14-webrtc-alias.md "Open item", plus reads of the installed packages.
`rnw/` = node_modules/react-native-webview 13.16.1; `rn/` = node_modules/react-native/ReactAndroid/src/main/java/com/facebook/react. -->
- **The gap.** A sandboxed `allow-scripts` frame can navigate itself (`location.href`/`assign`, `<meta refresh>`, an `<a href>` click), and the GET reached a canary on desktop Chromium and WebKit. CSP, sandbox and neutralization have no control for it. #64's guideline 4.7 argument says mini-apps "have no network access".
- **Mounts.** Two `<WebView>`s exist: `src/host/launcher/MiniAppView.tsx:129-141` and `DevProbeScreen.tsx:67-77`. Both pass `source={{ html: RUNTIME_HTML }}` with no `baseUrl` and no `onShouldStartLoadWithRequest`. Privacy and support links open through `Linking.openURL` (compliance design.md:73).
- **The runtime page needs no network.** The outer page is inline style and script (`build/assemble.mjs:185-209`). The srcdoc frame runs under `LOCKED_CSP` with `default-src 'none'` and `img-src data:` (`:17-27`). Bundles arrive by `postMessage` from host-held source (`src/host/launcher/deliver.ts:62-75`). The only URL literals in `src/runtime/web/` are probe targets that must fail (`probes.js:48,60-62,138`), and no probe expects a network success.
- **Base URL.** Android loads `html` with `loadDataWithBaseURL(baseUrl ?: "")` (`rnw/android/.../RNCWebViewManagerImpl.kt:385-398`); iOS uses `loadHTMLString:baseURL:` with `about:blank` (`rnw/apple/RNCWebViewImpl.m:836-846`). Neither is a network load.
- **No supported prop.** No prop blocks network loads on either platform (no `blockNetwork` or `ContentRule` anywhere in `rnw/android/src`, `rnw/apple`, `rnw/src`). iOS's `limitsNavigationsToAppBoundDomains` (`RNCWebViewImpl.m:478-484`) is an allowlist keyed to `WKAppBoundDomains`. Android's `RNCWebViewConfig` hook is dead: `mWebViewConfig` is a private no-op with no setter (`RNCWebViewManagerImpl.kt:40,74`).
- **The JS navigation guard fails open on Android.** `shouldOverrideUrlLoading` waits 250 ms for JS and then allows the load (`rnw/android/.../RNCWebViewClient.java:42,112-115`), and allows with a JS debugger attached (`:130-138`). `RNCWebViewClient` doesn't override `shouldInterceptRequest`.
- **Android extension point.** `RNCWebViewManager` is public, with a public no-arg constructor and `protected createViewInstance(ThemedReactContext)` (`rnw/android/src/newarch/.../RNCWebViewManager.java:37,43-46,60-64`; `newArchEnabled=true`, `android/gradle.properties:44`). `RNCWebViewPackage` is a public `TurboReactPackage` whose `createViewManagers` returns that manager and whose `getModule` serves `RNCWebViewModule` (`RNCWebViewPackage.java:17-54`). `RNCWebViewWrapper.webView` is public (`RNCWebViewWrapper.kt:23`).
- **Android ordering.** `ViewManager.createViewInstance` calls `createViewInstance(ctx)`, then `addEventEmitters`, then `updateProperties` (`rn/uimanager/ViewManager.java:224,227,229`), which ends in `onAfterUpdateTransaction` (`:104`), where the pending source loads (`RNCWebViewManagerImpl.kt:271-276`). A setting applied inside `createViewInstance(ctx)` precedes every load.
- **Android duplicate managers.** Bridgeless resolution fills one map over the packages in order, so the last manager with a given name wins and a duplicate goes unreported (`rn/runtime/ReactInstance.kt:531-533`, TODO T173624687). The generated `PackageList.java` lists `new RNCWebViewPackage()`; the Fabric component descriptor is registered separately, in the generated `autolinking.cpp`. The app builds its list at `MainApplication.kt:16-20`.
- **Chromium semantics of `setBlockNetworkLoads(true)`.** `android_webview/browser/network_service/net_helpers.cc` `UpdateLoadFlags` maps it to `LOAD_ONLY_FROM_CACHE | LOAD_SKIP_CACHE_VALIDATION`. `aw_proxying_url_loader_factory.cc` `InterceptedRequest::Restart()` applies those flags and handles main-frame and subframe requests. `aw_content_browser_client.cc` `WillCreateURLLoaderFactory` installs that proxy for every factory that has a frame, navigations included (chromium `main`, read 2026-09-14). WebSocket and WebRTC don't pass through it.
- **iOS extension point.** Each web view gets a fresh `WKWebViewConfiguration` and `[WKUserContentController new]` (`RNCWebViewImpl.m:423-512`, `:470`). The only creation site is `[[RNCWKWebView alloc] initWithFrame:configuration:]` in `didMoveToWindow` (`:515-519`), and `RNCWKWebView` doesn't override that initializer (`:51-57`). A recycled Fabric view rebuilds its web view through the same path (`rnw/apple/RNCWebView.mm:77-79`). Nothing in the package removes content rule lists; `resetupScripts:` removes only user scripts and handlers (`:1831-1832`). A popup from a subframe is loaded into the same web view with `loadRequest:` (`:390-405`).
- **WebKit semantics.** `Source/WebCore/contentextensions/ContentExtensionsBackend.cpp` `processContentRuleListsForLoad` evaluates `TopDocument` and `ChildDocument` loads like other resources and returns early only for `data:` URLs (WebKit `main`, read 2026-09-14). `url-filter` has no `|` operator.
- **iOS project.** No bridging header; ARC is on at project level (`project.pbxproj:322`); deployment target 15.1.
- **Probe constraints.** `src/host/logging/test/logging.suite.ts:61-68,457-475` fails any `console.*` call in `src/host` outside a hand-listed probe set, and any `[whim]` literal. `synthrun/builder.ts:119-132` `buildCandidateSource(source)` compiles a mini-app under the production bundle contract, pinned to `build/build.mjs` by `synthrun/test/acceptance.ts`. The server-side attack this mirrors is `synthrun/test/isolation.ts:310-352`.
